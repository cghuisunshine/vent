Learning goals

By the end, you can:

  • Explain Build–Measure–Learn and validated learning.
  • Design an MVP that tests one key hypothesis.
  • Choose metrics that are actionable (not vanity).
  • Decide when to pivot vs persevere using explicit criteria.

The core loop: Build–Measure–Learn

Build

  • Create the smallest thing that tests a hypothesis.
  • The goal is learning, not shipping for its own sake.

Measure

  • Collect data tied to the hypothesis.
  • Prefer cohort/behavioral metrics over totals.

Learn

  • Turn results into a decision: improve, change direction, or stop.
  • Write down what you learned so the team doesn’t “re-learn” later.

Hypotheses (what to test)

Value hypothesis (do users get value?)

  • Example: “Users complete onboarding without help.”
  • Example: “Teams use feature X weekly because it saves time.”

Growth hypothesis (can it spread sustainably?)

  • Example: “Referral invites convert at ≥ 10%.”
  • Example: “Paid acquisition yields LTV:CAC ≥ 3:1.”

A good hypothesis is

  • Specific (who, what behavior, by when)
  • Measurable (metric + threshold)
  • Timeboxed (decision date)

MVP patterns (choose one intentionally)

Concierge MVP

  • Do the work manually behind the scenes.
  • Best for: proving demand and workflows.

Wizard-of-Oz MVP

  • Looks automated, but is partially manual.
  • Best for: testing product experience without full build.

Landing page MVP

  • Measure interest through signups or intent.
  • Best for: early positioning and segment fit.

Prototype/demonstration MVP

  • Interactive mock or limited prototype.
  • Best for: usability and comprehension tests.

Rule: MVP is “minimum” for learning, not “minimal quality.” Be honest about constraints.

Metrics that drive decisions (not vanity)

Actionable metrics

  • Behavior-based: activation, retention, repeat use, conversion.
  • Cohort-based: users who started in week N tracked over time.
  • Tied to a change: if we do X, metric Y should move.

Vanity metrics (use carefully)

  • Total users, total revenue, pageviews without segmentation.
  • They can hide churn and poor retention.

A lightweight framework

  • Activation: % who reach the “aha moment”
  • Retention: % who return/use weekly
  • Referral: invites sent and conversion
  • Revenue: conversion to paid and expansion

Pivot vs persevere

Pivot signals

  • Strong interest but poor retention → value not delivered.
  • Retention but no growth channel → distribution problem.
  • Engagement only in a narrow segment → repositioning needed.

Common pivot types

  • Zoom-in (one feature becomes the product)
  • Zoom-out (product becomes a feature)
  • Customer segment (different users)
  • Customer need (different problem)
  • Channel (different distribution)
  • Revenue model (pricing/monetization change)
  • Technology/platform (different implementation)

Decision rule

  • Before you run experiments, define: if metric ≥ threshold by date → persevere.
  • Define: if metric < threshold → pivot (or stop).

Continuous improvement (process, not just product)

“Five whys” for recurring failures

  • When something breaks repeatedly, ask “why?” five times.
  • Fix the system cause (tooling, training, process), not just the symptom.

A 6-week lean cycle (practical cadence)

Week 1 — Problem clarity

  • Interview users; identify top 3 pains.
  • Write 3 value hypotheses and pick one to test.

Week 2 — MVP build

  • Build the smallest testable version (or run concierge).
  • Prepare measurement and instrumentation.

Week 3 — Run the test

  • Recruit target users; observe behavior.
  • Collect metrics; log qualitative notes tied to hypotheses.

Week 4 — Analyze and decide

  • Compare results to thresholds.
  • Choose: iterate, pivot, or stop.

Week 5 — Strengthen growth

  • Test one growth hypothesis (channel or referral).
  • Track cohort results; avoid totals-only reporting.

Week 6 — Systemize learning

  • Update the experiment backlog.
  • Improve measurement; publish a short learning report.

Exercises

Exercise 1 — Write three hypotheses

For each, include:

  • user segment
  • behavior
  • metric
  • threshold
  • timebox

Exercise 2 — Pick an MVP

  • Choose one MVP pattern and explain why it is the minimum needed to learn.
  • List what you deliberately will not build yet.

Exercise 3 — Define pivot criteria

  • Write one condition for persevere and one for pivot.

Quiz (self-check)

  1. What is validated learning?
  2. Give one example of a value hypothesis and its metric.
  3. Why are cohorts useful?
  4. What is an MVP’s primary purpose?
  5. Name two pivot types and when you might use them.

Answer key (short)

  1. Learning proven by evidence that informs decisions.
  2. Example: “40% of users complete onboarding” measured by completion rate.
  3. Cohorts reveal retention and behavior over time instead of totals.
  4. To test a hypothesis with minimal effort and time.
  5. Customer segment pivot when a different user group shows stronger fit; channel pivot when acquisition doesn’t work.
